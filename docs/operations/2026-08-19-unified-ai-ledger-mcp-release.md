# 统一 AI、个人账本与 Lumino MCP 发布验收

本文是本次实施的发布门禁和上线后检查清单。不得在命令输出、截图、仓库或日志中记录密码、API Key、Cookie、Bearer Token 或真实私密内容。

## 发布内容

- 每个用户独立的基础账本：收支、金额、分类、发生时间、备注、月度汇总；AI 可以在 100 个自定义分类上限内新增分类。
- 待办服务由 REST、网页 AI 与统一 MCP 共用，并保持用户隔离。
- `/chat` 的每条消息先经过私人 Agent 大模型路由，自动选择普通对话、账本、待办、博客或 Library；模块入口仅开放对应工具。
- 统一 MCP 位于 `/api/mcp/lumino/`；旧 `/api/mcp/blog/` 和 `/api/mcp/library/` 保持兼容。
- 网页博客先生成预览，用户确认后才保存为私密草稿；普通更新不接收也不改变公开/发布字段。
- MCP 博客创建默认请求公开：仅 `blog:publish` 与 `allow_auto_publish` 同时开启时公开，否则安全降级为私密草稿。
- Library 新增前先查询，服务端对标题、作者、年份和 URL 做归一化去重；同名冲突必须由用户选择更新或不同版本。

## 发布前门禁

在本地 `master` 且工作树干净时执行：

```bash
cd backend
venv/Scripts/python.exe -m pytest -q
venv/Scripts/python.exe -m compileall -q app

cd ../frontend
npx tsc --noEmit
npm run lint
npm run build
```

确认以下事项：

- Alembic 单一 head 为 `c8d7f1a2b304`，包含 24 小时有效的网页博客待确认提案表。
- 测试覆盖不同用户的账本、分类、待办与撤销隔离。
- MCP Token 只保存哈希，原始值只在签发后显示一次；停用立即生效。
- 非博客作者看不到网页 AI 的 Blog 工具；非超级管理员看不到 Library 工具，发证接口也拒绝不匹配的作用域。
- 测试数据不使用真实博客正文、聊天截图或用户隐私。

## 生产发布

只从服务器的干净 `master` 运行：

```bash
cd /opt/lumino
./scripts/deploy-production.sh
```

脚本会按差异执行依赖安装、`alembic upgrade head`、前端构建、PM2 重启和本机健康检查。完成后确认 `pm2 status` 中 `lumino-backend` 与 `lumino-frontend` 均在线，并记录部署 commit，不记录任何密钥。

## 上线后功能检查

### 1. 管理后台用户信息

- 以超级管理员登录“用户账号管理”。
- 用户总数必须大于零，并能显示历史 `.local` 邮箱账号；横向滚动后权限列仍可见。
- 随机选择一个非敏感测试账号，核对用户名、角色、加入时间和账号状态。
- 浏览器网络面板中的 `GET /api/admin/users` 应返回 200；不得把响应正文复制到工单或日志。

若页面显示 0 个账号，先检查该请求的状态码与后端日志中的响应校验错误。不要直接修改用户数据，也不要把输出模型的邮箱字段恢复成 `EmailStr`。

### 2. AI 服务连接自检

- 在“系统全局配置 → AI 服务商与 API 管理”选择已配置服务商。
- 界面显示的默认模型必须与“测试连接”实际请求的模型一致。
- 分别执行“测试连接”和“获取模型列表”；成功时记录模型名、耗时与检查时间，不记录 API Key。
- 失败时核对结构化错误分类：网络、鉴权、产品未开通、模型不可用、限流、余额或未知错误，并按界面建议处理。
- “产品未开通”是上游服务状态，不应通过反复改 Key、切换列表第一项或重启 Lumino 掩盖。

### 3. 账本与待办

- 使用两个测试用户分别新增一笔账与一条待办，双方列表均只能看到自己的数据。
- 用网页 AI 输入一条金额明确的记账指令，确认回执、月度汇总和撤销都生效。
- 让 AI 创建一个新分类，确认只出现在当前用户分类中；同名分类不会重复创建。
- 用统一 MCP 重复提交相同幂等键，确认只生成一个业务对象。
- 在账本入口输入“8.17 午饭16.79，烟36，8.18 午饭21烟20”，确认拆成四笔并自动使用餐饮、烟酒分类及正确日期，不再追问可推断分类。
- 在待办入口输入“提醒学 Harness”，确认创建无截止时间、无提醒时间的待办，不再强制追问时间。

### 4. 博客提案与私密预览安全

- 在网页主对话和博客管理入口使用无隐私内容生成博客，确认先出现完整预览卡片，数据库中尚无文章；点击“保存为草稿”后才创建 `draft`，取消不写入。
- MCP 新建时，Token 同时具备 `blog:publish` 和 `allow_auto_publish` 应默认公开；关闭自动发布的 Token 必须创建私密草稿并返回降级提示。
- 普通内容更新前后 `is_public`、`is_published` 与 `published_at` 必须一致。
- 保留现有公开预览能力，并验证 owner-only 私密预览仅允许作者或超级管理员访问。
- 不改变现有真实草稿的状态；不要为冒烟测试公开真实正文。

### 5. MCP 权限

- 无 Token 请求统一端点应为 401；停用 Token 后下一次请求应立即失败。
- 普通用户凭据只能访问绑定用户的账本、待办与其获权博客；不能签发或调用 Library 作用域。
- MCP 响应不得包含密钥、Cookie、数据库连接信息或异常堆栈。
- 旧 Blog MCP 与 Library MCP 至少各执行一次只读工具，确认兼容客户端未受影响。

### 6. Library 查询与去重

- 使用超级管理员的统一 MCP 先搜索一个无隐私测试标题，再新增该卡片。
- 用不同大小写、首尾空格或 URL 尾斜杠重复新增，必须返回“已存在”且卡片总数不变。
- 用同分类、同标题但不同作者或年份新增，必须返回冲突；明确选择更新现有条目或作为不同版本后才能继续。

### 7. 2C2G 资源与进程自检

- `pm2 status` 只允许一个 `lumino-backend` 应用和一个 `lumino-frontend` 应用；后端内部 worker 数按部署配置核对，不得遗留额外开发服务器或重复前端进程。
- 发布构建期间 CPU/内存短时升高可以接受；构建和重启结束后再次检查进程树、系统负载、可用内存和 swap，确认构建进程已退出且资源持续回落。
- 若 CPU 或内存持续超过 90%，先只读检查进程 PID、父子关系、启动时间和命令行，再按部署脚本管理对应 PM2 应用；不要盲目重复启动或整机重启。

## 回滚

应用回滚应先恢复上一稳定 commit，再按同一发布脚本重新构建和重启。数据库迁移新增了账本、行动审计与统一 MCP 表；若已经产生用户数据，不得直接 `alembic downgrade` 或删表。需要数据库回退时先备份并制定数据保留方案，经人工确认后执行。
