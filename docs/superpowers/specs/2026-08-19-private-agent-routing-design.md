# Lumino AI 私人 Agent 路由与确认设计

## 背景

Lumino 的目标不是在若干页面旁边增加互不关联的 AI 输入框，而是形成一个能理解用户对话、选择能力并执行真实操作的私人 Agent。当前实现有两个偏差：

- 主聊天先用关键词正则判断是否属于动作请求。未命中正则的自然表达会进入普通聊天模型，可能出现“口头说已记录，但数据库没有写入”的假成功。
- 账本、待办等模块入口虽然调用行动规划模型，但提示词过度保守，对常见分类、部分日期和可选字段也要求用户补充，削弱了自然语言入口的价值。

## 目标

- 主 AI 对话的每条用户消息第一步都交给大模型理解，不再由关键词正则决定是否调用工具。
- 私人 Agent 当前可以自动选择并执行四类核心能力：记账、待办、博客和 Library。
- 模块入口预先绑定对应能力范围，使“账本入口”默认调用账本工具，“待办入口”默认调用待办工具，“博客入口”默认调用博客工具。
- 网页与 MCP 共用领域服务和 `ActionExecutor`，确保权限、幂等、审计、撤销和博客发布规则一致。
- 只对真正缺少关键事实的指令追问；能根据常识、上下文和当前时间可靠推断的字段直接补全。
- 禁止普通聊天模型在没有行动回执时声称已经完成真实写入。

## 非目标

- 本期不增加转账、预算、周期账单、多币种和共享账本。
- 普通用户不能通过私人 Agent 修改全局 Library；超级管理员可以让 Agent 先查询现有收藏，去重后新增或更新 Library 内容。
- 本期不增加后台常驻自主任务、定时巡检或未经用户消息触发的主动执行。
- 网页内部不通过 HTTP 再调用 MCP 服务，也不向浏览器下发 MCP Token。

## 总体架构

```text
主 AI 私人助手 ── PrivateAgentRouter 自动选择工具 ─┐
账本/待办/博客入口 ── ContextAgent 限定工具范围 ───┼─ ActionExecutor ─ 领域服务 ─ 数据库
Codex 等外部客户端 ── Lumino MCP 权限适配 ─────────┘
```

网页和 MCP 使用相同的执行层，但入口职责不同：

- `PrivateAgentRouter` 负责理解主聊天消息，并返回普通聊天、直接执行、要求澄清或博客提案；超级管理员的可用工具中还包含 Library 查询和写入。
- `ContextAgent` 已知当前模块，不再判断业务类型，只在该模块允许的工具内提取参数和执行。
- MCP 是外部客户端协议适配器。网页直接调用内部执行层，避免网络回环和长期凭据暴露。
- `ActionExecutor` 是唯一真实写入口。没有成功的 `AIActionRun` 和行动回执，就不能向用户回复“已记录”“已创建”或“已保存”。

## 主对话路由

每条主聊天消息都经过模型路由，输入包含：

- 当前用户消息；
- 当前会话最近的文本上下文，用于理解“金额是 50”“同意保存”等追答；
- 当前上海时区日期与时间；
- 当前用户有权使用的工具定义；
- 尚未处理的博客提案摘要。

模型必须返回以下一种路由：

- `chat`：没有真实写入意图，继续调用页面顶部选择的普通聊天模型并保持原有流式回复。
- `execute`：参数已足够，调用一个或多个工具并返回行动回执；Library 新增必须先完成查询与去重。
- `clarify`：缺少无法可靠推断的关键事实，只提出一个最小问题，不执行写入。
- `propose_blog`：生成博客标题、摘要和正文预览，但暂不写入数据库，等待网页用户确认。

普通聊天允许多一次轻量路由调用。路由默认使用系统 Agent API；普通回答仍使用用户在当前会话选择的模型。

## 模块入口

模块入口仍调用大模型，但不再进行全局业务分类：

- 账本入口只提供账本工具，可一次拆分并记录多笔收入或支出。
- 待办入口只提供待办工具，默认创建待办。
- 博客入口只提供博客生成、草稿确认和博客更新工具。
- Library 管理入口只提供 Library 查询、去重、新增和更新工具，并且只向超级管理员开放。

如果用户在错误模块提出其他能力，例如在账本入口要求写博客，Agent 应说明当前入口只处理账本，并提示前往私人助手；不得跨模块静默执行。

## 推断与追问规则

### 账本

- 金额必须明确且大于零；缺少金额时追问。
- “午饭、晚饭、早餐、吃饭、外卖”推断为“餐饮”。
- “烟、香烟、酒、啤酒、白酒”推断为“烟酒”；分类不存在时允许为当前用户创建自定义分类。
- “工资、奖金、报销到账”等语义推断为收入，其余消费语义默认为支出。
- `8.17`、`8 月 17 日` 等部分日期补当前年份；未提供日期使用当前上海时间。
- 一句话中出现多组日期、事项和金额时拆成多笔动作，例如“8.17 午饭16.79，烟36，8.18 午饭21，烟20”生成四笔支出。
- 分类可由常见语义推断，不因用户没有手工说出分类而追问。

### 待办

- “提醒学 Harness”直接创建标题为“学习 Harness”的无截止时间、无提醒时间待办。
- 未写优先级时使用 `medium`，未写状态时使用 `pending`。
- 用户给出可确定的日期与时间时解析为上海时区。
- 用户明确要求在某个时间段提醒，但仍无法得到可执行时刻时才追问，例如“明早提醒我”需要具体时间。

### 博客

- 网页私人助手或博客入口收到“写一篇关于 X 的博客”时，先生成完整正文预览并创建待确认提案，不立即保存。
- 用户点击“保存为草稿”或在同一会话明确回复“同意保存”后，才调用 `create_blog_post`；网页创建结果始终为私密草稿。
- 用户取消、改写或提案过期时不得写入博客表。
- 网页中的普通博客更新不得改变 `is_public`、`is_published` 和 `published_at`。
- MCP 创建博客时默认请求公开：Token 开启 `allow_auto_publish` 时创建并发布；Token 未开启时只创建草稿，并在响应中明确说明没有公开。
- MCP 更新博客始终保持原发布状态；显式发布工具继续要求 `blog:publish` 作用域和 `allow_auto_publish`。

### Library

- 超级管理员在主私人助手或 Library 管理入口中可以说“把《某本书》添加进 Library”“收藏这部电影”等自然语言指令。
- Agent 在新增前必须先调用 Library 查询能力，不能仅凭当前对话直接执行新增。
- 去重时先归一化类别、标题、创作者、年份和 URL：忽略标题首尾空格、连续空格与大小写差异；有 URL 时优先按规范化 URL 判断同一条目。
- 类别、规范化标题及创作者/年份一致，或规范化 URL 一致时，视为已有收藏。Agent 返回“已存在”及现有条目摘要，不创建重复卡片。
- 标题相同但创作者、年份或类别冲突时，不擅自覆盖；Agent 应提出一个最小确认问题，让用户选择更新现有条目或作为不同版本新增。
- 确认不存在后，Agent 才调用 `upsert_library_media_card`，并返回可撤销的行动回执。
- 用户明确要求修改已有收藏时，Agent 必须先查询并取得稳定的 `card_id`，再执行更新，不能通过模糊标题直接覆盖。
- 外部 Library MCP 同样执行查询优先和服务端去重；即使客户端跳过查询，领域服务也必须阻止完全重复的收藏卡片。
- 非超级管理员不会获得 Library 写工具；其请求不得产生写入，并应明确提示权限范围。

## 博客待确认提案

新增 `ai_action_proposals` 保存结构化待确认动作，避免只依赖聊天文本重新提取长篇正文：

- `id`、`user_id`、`session_id`；
- `tool` 与经过 Pydantic 校验的 `arguments_json`；
- `status`：`pending`、`confirmed`、`cancelled`、`expired`；
- `expires_at`、`created_at`、`resolved_at`；
- 确认后产生的 `action_run_id`。

提案只允许所属用户读取和确认，只能成功确认一次，默认 24 小时过期。确认仍通过 `ActionExecutor`，并使用提案 ID 形成稳定幂等键。

## 前端交互

- 主聊天的博客提案显示标题、摘要、正文预览，以及“保存为草稿”“继续修改”“取消”操作。
- 账本和待办直接执行后显示绿色行动回执与撤销按钮。
- Library 新增成功、已存在和需要确认必须使用不同状态：只有真实新增或更新才显示可撤销成功回执。
- 批量记账显示每笔独立回执和本次成功数量。
- 澄清回复不得显示成功样式。
- 如果模型生成了成功文案但没有行动回执，前端不展示“已完成”状态，后端也不保存该文案为成功结果。

## 权限、安全与失败处理

- 路由模型只能看到当前用户有权使用的工具；普通用户不可获得 Library 写工具，未授权博客用户不可获得博客工具。超级管理员可获得 Library 查询与写入工具。
- 所有写入继续执行用户隔离、作用域校验、幂等和审计。
- 博客草稿确认、MCP 自动发布与显式发布采用不同路径，不允许网页确认草稿顺带公开。
- 模型输出必须先通过结构化校验，再执行全部动作；无效工具或参数不产生写入。
- 批量动作逐笔返回结果；若模型计划本身缺少关键字段，则在执行任何一笔之前要求补充，避免同一批请求产生不可解释的半完成状态。
- 对上游模型错误返回清晰错误，不回退为伪造成功的普通聊天回复。

## 测试与验收

- 主聊天“记录，20号吃饭50”必须产生真实 `create_ledger_entry` 回执和数据库记录。
- 主聊天普通问答必须先经过 Agent 路由，再进入原流式聊天，且不产生业务写入。
- 账本入口“8.17 午饭16.79，烟36，8.18 午饭21，烟20”必须生成四笔、两种分类、两天日期的支出，不追问分类。
- 待办入口“提醒学 Harness”必须直接创建无时间待办。
- 只有金额确实缺失的“记一下午饭”才追问金额。
- 网页博客生成在确认前博客表不新增；确认后新增一篇私密草稿；重复确认不重复创建。
- MCP Token 开启自动发布时创建结果默认公开；关闭时结果保持草稿；两种情况下普通更新都不改变发布状态。
- 超级管理员要求添加 Library 收藏时必须先查询；完全重复的收藏不新增，同标题冲突项必须确认后才能更新或另存。
- Library MCP 客户端直接调用新增工具而未先查询时，服务端去重仍能阻止完全重复条目。
- 不同用户不能读取或确认彼此的博客提案，不能撤销彼此的动作。
- 旧 Blog MCP、Library MCP、公开博客和 owner-only 私密预览继续通过回归测试。

## 发布与观察

- 先在本地运行后端全量测试、TypeScript、Lint 和生产构建。
- 部署执行 Alembic 迁移后重启前后端，并检查 2C2G 服务器资源。
- 上线冒烟使用无隐私测试内容，核对真实数据库写入与行动回执，不复制用户聊天正文到日志。
- 监控路由为 `chat`、`execute`、`clarify`、`propose_blog` 的计数和失败类别，只记录类型与耗时，不记录原始用户消息。
