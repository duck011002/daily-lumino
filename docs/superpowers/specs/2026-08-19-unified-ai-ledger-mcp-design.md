# Lumino 统一 AI、记账与 MCP 设计

日期：2026-08-19

## 目标

为每个 Lumino 用户增加独立的基础记账能力，并让网页表单、站内 AI 对话和 Codex MCP 使用同一套业务规则。统一能力覆盖记账、待办、博客和 Library，同时保留现有博客与 Library MCP，避免破坏已有客户端配置。

## 已确认的产品决策

- AI 对明确且可验证的指令直接执行，执行后展示结构化回执和撤销入口。
- 记账第一版只包含收入、支出、金额、分类、发生时间、备注和月度统计。
- 第一版不包含账户余额、转账、预算、周期账单、多币种或共享账本。
- 每个用户拥有私有账本和分类，第一版币种固定为 CNY。
- AI 可以新增分类，但必须先匹配已有分类与同义词，避免产生“早餐”“午饭”等碎片分类。
- 网页提供一个全站统一 AI 助手，各模块增加携带当前上下文的快捷入口。
- Library 保持现有全站资料模型，只有超级管理员能通过 AI 或 MCP 写入。
- 新增统一 Lumino MCP，同时保留现有博客 MCP 和 Library MCP。
- 博客公开发布继续遵守作者权限和 `allow_auto_publish`，普通内容更新不能改变发布状态。

## 当前系统与已确认故障

### 当前能力

- 博客已有独立 FastMCP 服务、作者绑定 Token、草稿创建、内容更新和受控发布。
- Library 已有独立 FastMCP 服务，只允许超级管理员维护全站书房资料。
- 待办已有按用户隔离的 REST CRUD 和网页列表，但没有 MCP，字段使用普通字符串，API 与权限测试不足。
- 网页聊天目前只执行普通文本流式补全，没有模型工具调用或业务执行循环。

### 管理后台用户列表

生产环境的 `GET /api/admin/users` 可稳定复现 500。数据库中存在 `jgx@lumino.local`、`lfh@lumino.local` 等历史内部邮箱；`UserAdminResponse` 继承使用 `EmailStr` 的输入模型，响应序列化会拒绝保留域 `.local`，从而让整张用户表响应失败。修复必须区分“新用户输入校验”和“历史数据输出兼容”，不能通过删除历史用户解决。

### AI 服务商连接

截图中的服务商返回 `invalid_parameter_error`，含义是请求使用的产品当时未在服务商侧开通。2026-08-19 对当前默认模型 `qwen-flash` 和替代模型 `qwen3.7-flash` 的真实最小请求均成功，说明 Lumino 到服务商的网络和现有凭据当前可用。后台仍需改进：记录实际测试模型和时间、区分网络错误、鉴权错误、产品未开通、模型不可用和限流，并避免用历史 `is_reachable` 状态误导用户。

## 总体架构

新增领域服务层，作为所有入口的唯一写入路径：

- `LedgerService` 负责分类、账目、统计、软删除和恢复。
- `TodoService` 负责待办查询、创建、更新、完成和删除。
- `BlogActionService` 封装现有博客草稿和发布规则。
- `LibraryActionService` 封装现有全站书房维护规则。
- `ActionExecutor` 负责工具注册、权限检查、幂等、审计、结果标准化和撤销。

REST 路由、统一 MCP 和站内 AI 都调用领域服务，不允许 MCP 或聊天代码直接修改 ORM 对象。现有博客和 Library MCP 逐步改为复用领域服务，但端点、工具名和 Token 行为保持兼容。

## 记账模型

### `ledger_categories`

- `id`：主键。
- `user_id`：分类所属用户。
- `name`：展示名称，同一用户、同一收支类型下规范化后唯一。
- `entry_type`：`expense` 或 `income`。
- `is_default`：是否由系统初始化。
- `is_archived`：是否归档。
- `created_at`、`updated_at`：审计时间。

每位用户第一次读取分类或创建账目时初始化默认分类。支出默认包括餐饮、交通、购物、住房、娱乐、医疗、教育和其他；收入默认包括工资、奖金和其他收入。自定义分类最多 100 个。已有账目引用的分类只能归档，不能硬删除。

### `ledger_entries`

- `id`：主键。
- `user_id`：账目所属用户。
- `entry_type`：`expense` 或 `income`。
- `amount`：`DECIMAL(12, 2)`，只保存大于零的正数。
- `currency`：第一版固定为 `CNY`。
- `category_id`：所属分类。
- `occurred_at`：按 Asia/Shanghai 解释后的无时区数据库时间。
- `note`：可选备注。
- `source`：`web_form`、`web_ai` 或 `mcp`。
- `idempotency_key`：同一用户写入唯一，防止网络重试重复记账。
- `deleted_at`：软删除时间。
- `created_at`、`updated_at`：审计时间。

月度统计只计算未删除记录，返回收入、支出、结余、分类汇总和每日趋势。

## 待办加固

- 将 `priority` 收紧为 `low`、`medium`、`high`。
- 将 `status` 收紧为 `pending`、`completed`、`cancelled`。
- 所有查询和写入必须包含 `user_id` 条件。
- 自然语言日期以 Asia/Shanghai 解释。“明天下午”默认 15:00；只有日期而没有时间的指令不自动创建提醒时间。
- 第一阶段保留浏览器通知授权界面，但不宣称已具备可靠服务端推送；真正的推送提醒另立范围。

## AI 分类规则

- 先对名称做去空格和大小写无关的规范化匹配。
- 先匹配默认分类、用户自定义分类和同义词。
- 用户明确要求新增分类时直接创建。
- 稳定且明显的新领域可以自动创建，例如“宠物洗澡 80 元”创建“宠物”分类。
- 日常描述不得形成碎片分类，例如早餐、午饭、奶茶统一优先映射餐饮。
- 无法可靠判断时使用“其他”，但金额或收支方向不明确时不得写入，应追问用户。

## 统一 MCP

新增 `/api/mcp/lumino/`，使用独立 Bearer Token。Token 仅保存 SHA-256 哈希，包含绑定用户、启停状态和权限范围。

第一批权限范围：

- `ledger:read`、`ledger:write`
- `todo:read`、`todo:write`
- `blog:read`、`blog:write`、`blog:publish`
- `library:read`、`library:write`

Library 写权限只允许为超级管理员 Token 签发。博客发布范围不能绕过 `allow_auto_publish`。网页客户端永远不接收 MCP Token。

第一批统一工具：

- 记账：分类列表、新增分类、重命名、归档、创建账目、查询、修改、删除、月度汇总。
- 待办：创建、查询、修改、完成和删除。
- 博客：分类列表、创建草稿、读取、更新、私密预览信息和受控发布。
- Library：读取资料、更新资料、维护链接和收藏卡片。
- 公共：`undo_action`。

## 站内 AI 执行

现有聊天改为两阶段流程：先用模型生成结构化行动计划，再通过 `ActionExecutor` 执行业务工具，最后让模型根据执行结果生成自然语言答复。

- 支持原生工具调用的模型优先使用 function calling。
- 不支持的模型使用严格 JSON Schema 规划；无法解析时不执行。
- SSE 新增 `action_started`、`action_succeeded`、`action_failed` 和 `done` 事件。
- 一条消息可以包含多个独立动作，逐项执行和返回结果；单项失败不回滚其他成功项。
- 删除全部数据、公开发布等高影响操作必须有明确动词和明确对象。

## 审计、幂等与撤销

新增 `ai_action_runs`：

- 用户、来源、会话和工具名。
- 幂等键和结构化输入。
- 目标实体类型与 ID。
- 执行状态、标准化结果和错误分类。
- 修改前快照、撤销状态和时间。

网页 AI 写操作展示十分钟快捷撤销按钮；之后仍可在模块页面手工修改。MCP 返回 `action_id`，Codex 可调用 `undo_action`。撤销必须验证原用户和工具范围，并且只能成功一次。

## 网页体验

- 新增 `/ledger`，包含本月概览、快速记账、月份切换、账目列表、分类统计、每日趋势和分类管理。
- 工作台增加“我的账本”入口。
- `/chat` 保持完整会话体验，并显示行动过程与结果卡片。
- 登录后的公共布局增加统一 AI 快捷入口。
- 账本、待办、博客管理和 Library 管理页增加携带当前模块上下文的快捷输入。
- 手机端使用底部抽屉，桌面端使用右侧面板。
- 无权限工具既不展示，也不能通过直接请求调用。

## API 边界

记账 REST API 使用 `/api/ledger`：

- `GET /categories`
- `POST /categories`
- `PATCH /categories/{category_id}`
- `DELETE /categories/{category_id}`，语义为归档
- `GET /entries`
- `POST /entries`
- `PATCH /entries/{entry_id}`
- `DELETE /entries/{entry_id}`，语义为软删除
- `POST /entries/{entry_id}/restore`
- `GET /summary`

统一行动 API 使用 `/api/ai/actions`，只接受服务端注册工具和经过 Pydantic 校验的参数，不接受任意函数名、代码或 SQL。

## 错误处理

- 领域校验错误返回稳定错误代码和中文消息。
- MCP 将领域错误转换为可读工具错误，不暴露堆栈或凭据。
- AI 服务商错误按网络、鉴权、产品未开通、模型不可用、限流、余额和未知错误分类。
- 服务商自检返回实际测试模型、检查时间、延迟和错误分类。
- 用户列表中单个历史字段不得让整个管理接口失败。

## 测试与上线门禁

- 记账金额精度、跨月统计、分类查重、归档和软删除测试。
- 不同用户之间的账目、分类、待办和撤销隔离测试。
- REST、MCP 和网页 AI 对同一服务函数的行为一致性测试。
- MCP Token 范围、停用、绑定用户和博客发布权限测试。
- 重复请求幂等测试。
- AI 模糊输入不写入、明确输入直接写入和分类自动新增测试。
- 原生工具调用与 JSON Schema 降级测试。
- `/api/admin/users` 必须能返回包含历史 `.local` 邮箱的用户列表。
- AI 自检必须对真实默认模型发起最小请求，并展示实际模型、时间和分类后的错误。
- 现有博客更新不得改变发布状态；旧博客与 Library MCP 回归通过。
- 后端完整测试、前端类型检查、Lint 和生产构建通过后才能部署。
- 生产迁移前备份数据库；迁移、服务重启、健康检查和真实浏览器验收全部记录。

## 实施分段

2. 建立记账核心、REST API 和网页账本。
3. 抽取待办服务并增加待办 MCP 能力。
4. 建立统一 Token、ActionExecutor、审计、幂等和统一 MCP。
5. 改造站内聊天工具执行循环和结果卡片。
6. 接入博客、Library 和四个模块快捷入口。
7. 完成全量回归、部署文档和生产验收。

## 非目标

- 第一版不实现银行或支付平台自动同步。
- 第一版不实现 OCR 账单导入、预算提醒、资产账户或家庭共享账本。
- 第一版不把浏览器通知包装成可靠的服务端提醒。
- 不删除或改变现有博客与 Library MCP 地址。
- 不在客户端、日志、错误消息或仓库中保存明文 Token、密码或 API Key。
